description: Handling service requests and changes - access, configuration changes, integrations, feature/product information, onboarding.

Treat the ticket as a request to fulfil, not a fault to diagnose.

1. Identify exactly what is being requested and what information is required to fulfil it
   (account, product/plan, environment, approver, deadline).
2. Search for historical cases with the same request pattern; note the standard fulfilment steps
   and any prerequisites or approvals mentioned in their resolutions.
3. If historical cases show the request needs approval or a specific team, say so explicitly.
4. If the request is ambiguous (e.g. which product, which integration, which users), it is better
   to ask one focused clarification question than to guess.
5. For change requests, include risks / rollback considerations only if the evidence mentions them.
6. Use category statistics if you are unsure whether the request belongs to this queue.
